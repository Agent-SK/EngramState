Technical note 04 · Scaling

Scaling EngramState to larger tool repositories

The important question is not whether 24 tools work. It is which costs grow with the repository, which stay constant, and where retrieval quality begins to matter.

Execution cost stays local to the candidate

EngramState never loads the full state repository for one request. The retriever selects Top-K candidates and the executor loads one candidate state per attempt. This means the cost of a single state-loading + generation step does not increase just because the catalog contains more tools.

What does scale with tool count?

Similarity comparisons increase with the catalog size, just as they do in retrieve-then-prompt systems. In our 100-tool measurement, similarity computation plus Top-K scanning took only 0.0304 ms out of 24.1 ms total retrieval time—about 0.1% of retrieval latency.

Why Hit@4 matters

EngramState can traverse multiple candidates, so Hit@4 is often more operationally meaningful than Hit@1. At 206 tools, the MLP retriever still places the correct tool in the Top-4 about 95.63% of the time.

The retriever objective is weighted

The State Retriever is not trained by blindly adding every loss term with equal weight. The objective combines a retrieval loss, an auxiliary tool-classification loss, and a hard-negative ranking loss. The auxiliary coefficients are treated as hyperparameters and selected from values between 0 and 0.3.

L = L_retrieval
  + λ_cls  · L_tool_classification
  + λ_hard · L_hard_negative

This matters because the auxiliary tasks are useful regularizers, but allowing them to dominate can hurt the representation used for actual retrieval.

Offline compilation scales linearly

For RWKV-7 1.5B, Base + Corrective compilation for one tool is roughly 0.28 s. Extrapolating the same per-state measurement, 1,000 states take roughly 140 s on one RTX 3090. The cost grows, but it is paid offline and can be parallelized.

Common offline work vs EngramState-specific work

Function-calling systems already pay common preparation costs such as LLM fine-tuning and retriever training. In our setup, LLM fine-tuning takes 2.4 / 4.4 / 6.5 / 13.5 hours for the 0.1B / 0.4B / 1.5B / 2.9B RWKV-7 variants using 10k examples, 24 epochs, and eight RTX 3090 GPUs. The additional EngramState-specific step is state compilation, which is orders of magnitude smaller.
