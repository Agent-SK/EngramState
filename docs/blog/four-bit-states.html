Technical note 03 · Deployment

Storing recurrent states at 4 bits

Reusable states remove repeated prompt compute, but they introduce persistent storage. Quantization is what makes that trade practical at device scale.

EngramState stores a pair of recurrent states for each tool: Base and Corrective. Keeping those tensors in full FP16 precision is simple, but the storage cost grows linearly with the number of tools.

The storage trade

For RWKV-7 1.5B, the combined FP16 Base + Corrective representation is approximately 24.76 MiB per tool. At 100 tools, that would already be roughly 2.42 GiB.

That is too expensive for a design intended to scale across a mobile tool catalog.

4-bit per-channel quantization

EngramState applies 4-bit per-channel linear quantization to both stored states. This reduces the combined storage to approximately 6.19 MiB per tool, a 4× reduction from FP16.

RWKV-7 1.5B, Base + Corrective
FP16  : 24.76 MiB / tool
4-bit :  6.19 MiB / tool
Why 4 bits? The choice is practical rather than a claim that lower precision is impossible. Four-bit storage is byte-friendly — two values fit naturally in one byte — and is well supported by mobile inference stacks.

What about 3 bits?

Three-bit storage can reduce footprint further, and our experiments show it can remain close to the higher-precision baseline. The drawback is implementation complexity: 3-bit values are not byte-aligned, so packing and unpacking become more awkward on real devices.

For a research system targeting practical deployment, 4-bit storage provides a useful balance between compactness, implementation simplicity, and accuracy.

Storage is only one side of the design

The runtime does not need to load every stored state. EngramState retrieves a small candidate set and selectively loads states as needed. Persistent storage therefore scales with the catalog, while active runtime state remains tied to the retrieved candidates.
